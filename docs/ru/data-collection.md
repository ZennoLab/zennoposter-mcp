# Сбор данных

ZennoPoster собирает **агрегированную телеметрию** по использованию PublicApi.
На этой странице описано, что именно собирается и что не собирается, с какого момента и как
данные обрабатываются.

**Сбор начат:** ZennoPoster **7.9.3** · ZennoDroid **2.6.2** (планируется).

## Что собирается

### Дневной свод использования PublicApi

По таймеру (и ещё раз при штатном завершении работы) продукт отправляет дневной свод на
`api/statistics/publicapi-usage`. Тело содержит два списка: `usage` и `issued`.

В `usage` — по строке на каждое сочетание ключа, операции, клиента и редакции за день:

| Поле | Что содержит |
|---|---|
| `date` | UTC-дата, к которой относятся счётчики (YYYY-MM-DD) |
| `keyId` | Идентификатор ApiKey — **никогда не само значение ключа** |
| `keyKind` | `user` для выпущенного вами ключа, `internal` для ключа, который продукт выдаёт собственным MCP-сайдкарам |
| `clientType` | Значение заголовка `X-ZP-Client`, или `direct-http`, если заголовок отсутствует |
| `operationId` | Вызванная операция PublicApi, например `tasks_list` |
| `edition` | Редакция продукта (`Pro`, `Lite`, `Standard`, `Demo`, `ProjectMaker`, `ZennoBox`, `ZP8`) либо `unknown` |
| `count` | Число авторизованных вызовов за этот день именно для такого сочетания |

Это **дневной агрегат, а не журнал запросов**: нет меток времени отдельных вызовов, нет
аргументов и результатов. Но разбивка идёт по операциям и ключам — это не одно общее число
за сутки.

В `issued` — по строке на каждый выпуск ключа:

| Поле | Что содержит |
|---|---|
| `date` | Дата выпуска ключа |
| `keyId` | Идентификатор ApiKey — никогда не само значение ключа |
| `keyKind` | `user` или `internal` |
| `edition` | Редакция продукта на момент выпуска |

На стороне сервера учётная запись берётся из claim `sub` того токена, которым отправлен свод,
и строки хранятся в разрезе учётной записи.

### Счётчики OTel

Вместе со сводом в коллектор телеметрии уходят два счётчика:

```
zp7_publicapi_calls_total{operationId, keyKind, clientType, productName, productVersion, os}
zp7_publicapi_keys_issued_total{keyKind, productName, productVersion, os}
```

В них **нет ни идентификатора ключа, ни идентификатора учётной записи** — только перечисленные
выше метки с низкой кардинальностью. В `os` — только версия ОС (`Windows 10`, `Windows 11`),
без номера сборки.

## Что НЕ собирается

- **Тела запросов и ответов** — никакого контента шаблонов, кода проектов, значений
  переменных, параметров действий, DOM-данных или любого пользовательского контента.
- **Значение ключа и его Label** — отправляется только идентификатор ключа.
- **Детали отдельного вызова** — ни метки времени конкретного вызова, ни аргументов, ни
  возвращённого значения, ни текста ошибки; только дневные суммы по сочетаниям.
- **Отклонённые вызовы** — счётчик срабатывает только на успешно авторизованном вызове,
  поэтому попытки, отклонённые с 401/403, не учитываются вовсе.
- **Данные браузинга и автоматизации** — никаких посещённых URL, данных форм, скриншотов.
- **IP-адреса и имена машин** — продуктом не отправляются.

## Хранение и обработка

Телеметрия доставляется по HTTPS на `zp7-service` (бэкенд ZennoLab). Данные
обрабатываются и хранятся в соответствии с
[Политикой конфиденциальности ZennoLab](https://zennolab.com/privacy).

Сбор включён по умолчанию для инсталляций с исходящим HTTPS-доступом к эндпойнту.
Продукт **не** блокирует запуск или функциональность при недоступности эндпойнта —
ошибки доставки логируются на уровне debug, а данные сохраняются до следующей попытки.

Дневные счётчики также хранятся на машине, в папке данных продукта
(`PublicApiUsage.ZennoPoster.json`, `PublicApiUsage.ProjectMaker.json`), чтобы после перезапуска
в течение дня счёт за этот день продолжался, а не начинался заново. В файле лежат те же строки
`usage`, что уходят на сервер, и ничего больше; строки прошедших дней удаляются из него после
доставки.
